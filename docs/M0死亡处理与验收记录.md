# M0 死亡处理与脚本验收

日期：2026-10-14。开发分支：`dev/m0-startup`，从干净的 main 创建；未改变 main 分支上的基线。

## 实现

- 玩家保留 Alive、DeathTick 和死亡时尚在场的自有泡泡数量；死亡后位置冻结，不占据新的移动阻挡。
- 同刻全部爆炸覆盖先合并，存活者才判定死亡；已死亡玩家跳过之后的受击，死亡事件只产生一次。
- 先判死亡再执行终点放置，死亡取消该请求；后续脚本动作整体忽略，记录原因，不因冻结位置重新校验路径而报错。
- 已放泡泡保留原归属和到期时刻，不随所属玩家死亡而删除。
- 验收预期移至脚本 expected，核对最终玩家状态、死亡时刻、死亡时遗留泡泡数、实际放置与爆炸时间、逐格地图及取消次数；不写死必须全部存活。
- UI 输出显式存活与死亡时刻，地图灰色叉号与状态列表展示死亡，轮数和完成摘要根据脚本更新。

## 死亡脚本的六轮流程

| 轮次 | 玩家 1 的计划 | 实际预期 |
| --- | --- | --- |
| 1 | A1→B1，终点放泡泡 | t=1 放置 #1，t=4 到期 |
| 2 | B1→A1 | 返回出生格 |
| 3 | A1→A2，终点再放泡泡 | t=3 放置 #2，t=6 到期 |
| 4 | A2→A1，计划终点放置 | #1 引爆并杀死玩家；终点放置取消，#2 保留 |
| 5 | 计划向下并放置 | 整体忽略，不移动、不新增泡泡 |
| 6 | 计划向右并放置 | 整体忽略；#2 仍引爆，不重复死亡 |

其他三人全程等待，最终位于各自出生格。仅 C1、A3 箱子被毁，箱子 327、硬墙 100、在场泡泡 0，玩家 1 死亡于 t=4/A1，其余三人存活。
