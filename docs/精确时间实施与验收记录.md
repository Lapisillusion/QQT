# 精确时间实施与验收记录

日期：2026-10-16。依据用户确认的质点归属、中心放置、准备跨线时检查阻挡、原速强制回退及同刻顺序实施。用户同时要求独立测试环境，并为每个讨论场景提供一份完整脚本。

## 实现范围

- 核心以约分后的分数 tick 运算和比较；分子／分母使用 long，中间乘积用 BigInteger，超出可表示范围明确失败，不回退浮点。默认零值等价于 0/1。
- 玩家同时保存质点坐标、逻辑归属格和已生效整数速度、容量、范围、寿命。成功跨线的半程当刻归目标格，失败的边界当刻及回退全程归原格。
- 每轮扫描下一次跨线、到中心、退回中心、泡泡到期和轮末，推进所有人的质点后统一裁决。跨线使用本批清理前环境，再处理到期与全部递归连锁、同批淘汰和胜负，存活者才执行中心放置并继续移动。
- 本轮遇阻只取消剩余计划，以原速度退回刚离开的中心；既往移动和放置保留，不主动改向、不回到轮初、不瞬移，不重试已处理的中心请求。回退途中死亡或比赛结束即停止。死亡者未执行的放置在实际死亡时刻取消，后续轮次只忽略其新计划。
- 同格叠放、连锁去重、射线穿过泡泡、墙／箱子截断、同刻旧地图和后续新地图均沿用相同核心；范围按泡泡所属玩家的已生效属性计算。
- 事件、轨迹和历史均由唯一所有者持有池数组，按实际需要扩容，归还旧数组；96 只是初始事件预留量。快照在锁内序列化，消息发送完成后才归还消息缓冲。
- UI 消息发送精确时间、质点坐标及分段轨迹；浏览器仅为绘制转换小数，按时间显示泡泡生成、爆炸、死亡和回退，途中爆炸不在轮末重新播放。玩家状态提示显示实际参数与质点坐标。

真实 AI、查询计费、道具获取与属性激活、持久化回放、暂停／单步及 500 tick 上限仍未实现。本次不增加这些功能，不改变正式默认地图与初始参数。

## 独立环境与脚本格式

不声明 initial 时保持原 21×21 地图、四角位置、速度 1、容量 3、范围 1、寿命 3，四份旧脚本无需修改。声明 initial 时使用独立环境；后续动作经过同一个 GameSimulation，不能跳过阻挡、容量、死亡或胜负判定。

| 字段 | 含义与校验 |
| --- | --- |
| initial.map | 当前支持 empty，21×21 全空地；UI 外圈与逻辑越界仍是边界 |
| initial.walls / crates | 可选格子坐标列表，用于必要障碍边界；箱子与墙不得重叠，默认均为空，不生成道具 |
| initial.players | 必须四人，编号 1～4 唯一；position 为可通行格子的中心，允许玩家同格 |
| speed / capacity / range | 玩家初始机制参数，可选，默认 1／3／1，必须为正整数 |
| lifetime | 玩家泡泡固定寿命，可选，默认 3，必须为正分数 |
| initial.bubbles | 可选初始泡泡：ownerId、position、placedAt、dueAt。按声明顺序分配编号，计入所属玩家在场容量，必须满足 placedAt≤0≤dueAt 且 dueAt=placedAt+所属玩家寿命 |
| rounds[].actions[].placements | 本轮预选中心坐标列表，包含起点；同轮不重复、不越界，必须在名义直线路径内；实际阻挡导致未到达时只跳过对应请求 |
| expected.players | 四人最终归属格、精确死亡时刻、死亡时遗留泡泡数；可声明精确 point 核对质点，避免只检查格子掩盖瞬移 |
| expected.bubbles | 声明全部初始及新放泡泡，核对实际放置、预定到期、实际引爆及来源；初始泡泡加 initial:true，explodedAt:null 表示仍保留 |
| expected.checkpoints | time、roundId 与玩家列表，核对指定事件点的格子归属、存活及质点坐标；roundId 区分同一时刻的旧轮终点与下一轮起点 |
| expected.events | kind、count 及可选 time／playerId／bubbleId／position／reason 筛选，核对精确次数，包括 count:0 禁止事件 |
| expected.end | 可选精确 tick 与 winnerId；null 胜者代表全灭平局。未声明时要求验收终点仍未产生竞技结果 |

JSON 输入的时间和质点分量可以使用整数或 {"numerator":1,"denominator":3}；UI 消息统一采用该整数对象形式。时间不会按显示小数舍入。roundId、totalTicks、玩家编号及格子坐标继续使用整数。

验收汇总 Placed 包含初始泡泡与本次新放置；事件 kind=placed 只表示本次动作实际放置，initialBubble 单独表示初始化，二者不会混淆计数。

初始泡泡用于隔离到期边界，其 placedAt 可在测试时间零点之前；这只描述初始事实，不模拟负时间历史，也不提供比赛进行中的远程放置能力。加载时发出 BUBBLE_INITIALIZED，后续到期或连锁完全按普通泡泡处理。示例字段可直接查看 [快慢玩家脚本](../scripts/precise-13-fast-blocks-slow.json)与 [跨线同刻到期脚本](../scripts/precise-15-disappears-at-entry.json)。

验证通过与比赛结束相互独立。一份完整验证脚本必须有完整初始条件、有限轮次的四人动作和明确预期，不要求为验证附加三人自爆；确需验证即时终局的脚本明确声明 end，并核对终局后不再出现事件。

- 01～06：跨线前／当刻／之后，以及四个移动方向的归属边界。
- 07～11：此前 A1 向右三格、B2 在 0／1/3／1 引爆，以及 1/6 进入、1/2 离开的精确边界。
- 12～18：中心才放置、速度 10 阻挡速度 1、提前消失、同刻消失、同刻新放置、中心到达同刻死亡、跨出覆盖格同刻爆炸。
- 19～25：回退途中受击、保留此前动作、成功请求不重复、容量释放后失败请求不重试、障碍清除不重启、离开与重新进入、已进入格内者的离开许可。
- 26～31：玩家交换、同格中心放置、多个中心分别计时、分数时刻递归连锁、同格去重、原射线穿透与射程限制。
- 32～39：硬墙、越界、回退途中立即获胜、分数同刻全灭、死亡取消全部后续请求、1/3+2/3 精确到期、同刻旧地图与后续地图。

36 份没有箱子。23／38／39 使用单箱补充环境：分别区分障碍清除后重启、同刻穿过刚毁箱子、后续仍被已毁箱子阻挡三类错误，属于其余空地图脚本无法识别的必要边界。

注意“泡泡提前消失就能通过”还要求玩家存活。慢速玩家一直在该泡泡的相邻格时，提前爆炸通常已经将其淘汰。14 因此让玩家爆炸时仍处覆盖外，之后进入已清空格；19 单独验证相邻格回退途中受击，避免以死亡掩盖通行判定错误。
