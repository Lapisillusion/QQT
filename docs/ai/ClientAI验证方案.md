# ClientAI 第一版验证输入与预期

本次四人对抗采用正式 21×21 地图，四类道具各 8 个，共 32 个；这是本次验证配置，不修改服务端默认玩法。参赛者为四个独立 C# 进程，使用相同算法和不同策略种子。出生和道具种子固定并记录，但不传给 AI 推断隐藏分配。

## 精确预测检查

通过 `QQT.ClientAI.Checks` 将客户端推演与独立 Core 实际模拟对照。预期在执行前声明：

| 输入 | 独立预期 |
| --- | --- |
| 速度 1 向右，目标泡泡恰在 1/2 到期 | 先阻挡，再按原格受击，t=1/2 淘汰 |
| 速度 2 向右，前方两格泡泡 t=1/5 先爆 | 初始位置安全；之后通过已清空路径，到 (2,0) |
| t=1/2 成功跨出旧格爆炸覆盖 | 存活，到 (1,0) |
| t=1/2 成功跨入新格爆炸覆盖 | 按新格淘汰 |
| 速度 3，第二格有箱子，回退后 t=3/4 爆炸 | 退回刚离开的 (1,0)，在该格受击；先前放泡保留并连锁 |
| 同刻两条射线遇同一箱子 | 全批使用旧地图，箱后玩家存活 |
| 射线遇另一泡泡并连锁 | 原射线继续，远端玩家淘汰 |
| 速度 3 在第一、第二中心放泡 | dueAt 分别为 10/3、11/3；未来运动与 Core 一致 |
| 拾取已露出火力，旧泡泡下一轮 t=5/2 爆炸 | 范围下一轮增加，命中旧范围之外的玩家 |
| 排队登记文档后复用接收数组接收新消息 | 文档仍保留原来的 type／playerId，不受缓冲改写影响 |
| 对手轮初容量已满，t=1/2 旧泡泡爆炸释放容量并在途中中心放置 | t=3/4 阻挡自身进入，回退至 (1,0)；新泡泡到期为 7/2 |

## 真实网络对抗

输入：启动对战 Server，创建 4 人自动模式、正式初始地形和四类随机道具各 8 个，启动 4 个独立 ClientAI。外部 UI 控制连接只负责创建、开局和记录，禁止给 AI 策略输入全局帧。

预期：四人完成登记；存活客户端每轮提交合法锁定计划，成功查询累计费用不超过 10，余额与回复一致；计划锁定后不再查询。不得靠断线、脚本耗尽或清理制造终局。持续运行至 `match.ended`，接受淘汰决出的胜负／全灭平局或 500 tick 平局，并如实报告。核对服务端事件、客户端实际收到的结果和 UI 终态一致。

证据：服务端完整 JSONL、四名 AI 分类决策／查询／消息日志、UI 记录、进程退出码和独立汇总。复盘说明每次淘汰、关键开路／增益／反击、查询收益、耗时与算法局限；单局不能证明胜率提升。
