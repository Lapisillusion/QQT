# 匀速移动、实际放置计时与途中引爆

真实 AI 的登记与开局：服务端分配玩家编号并绑定参赛连接，本局跨轮稳定，请求只能操作绑定玩家。四名 AI 均登记后由 UI 手动开始，再统一下发首轮观察；不足四人保持准备。准备阶段连接明确关闭或报错时释放席位并接受新连接登记。席位已满时明确拒绝额外登记，不设候补队列，席位释放后可重新申请。局末发送结束通知并关闭 AI 参赛连接，下一局重新连接、登记并分配编号。本文决策等待和模拟期间的掉线出局、不支持重连规则均适用于已经开始的对局；具体登记消息在实施时完善。首版本机 UI 的全局数据、运行控制和记录读取接口不校验访问凭据。

完整已确认规则见 [首版模拟规则_已确认版](首版模拟规则_已确认版.md)。本文保留时间模型与场景推演，演示数字不作为正式参数。

用户已确认每颗泡泡以实际放置时刻加固定寿命确定预定到期，并选择允许在对应途中时刻引爆。此规则替代此前只能在大 tick 或固定小步边界引爆的限制。统一同步决策、中心所在格瞬时受击和已经确认的主要同刻顺序保留。

## 当前已确认规则

- 格子地图保留角色跨格进度，按给定速度匀速移动，只在格子中心开始下一段移动。
- 协议格子位置使用从 0 开始的整数对 (x,y)，范围各为 0～20，x 向右、y 向下；A1=(0,0)，B2=(1,1)。JSON 采用 {"x":0,"y":0} 对象形式，放置计划使用格子坐标对象列表，实际放置按到达中心时刻执行。界面仍显示 A～U、1～21，跨格进度仍单独记录。
- AI 查询和动作请求携带 gameId、roundId、requestId；对局或轮次不匹配时拒绝，不扣费、不锁定计划。requestId 仅关联响应，查询重发成功仍扣费，动作重发不重复执行。
- 内部逻辑地图 21×21，尺寸不包含 UI 外圈墙。UI 在外侧绘制硬墙边框；越界按阻挡处理，爆炸停止于边界，视野只裁剪内部逻辑格。
- 四名玩家每局随机分配到内部地图四个角格中心，由服务端保存种子用于复现。每角仅预留出生格及两个向内相邻格为空地，共 3 格，不放墙或箱子，地图地形固定。
- 首版固定初始地图为 21×21，硬墙位于行、列序号同时为偶数的交点，如 B2、D2、B4、D4，直到 T20。共 100 墙、329 箱子、12 格出生预留空地，每局恢复此布局，见 [首版地图](地图布局_21x21_首版.md)。
- 所有玩家初始属性统一：速度 1 格/tick、容量上限 3 颗、爆炸范围每方向 1 格、寿命 3 tick、视野 R=2、每轮行动值 10 点。可调参数最终由配置文件提供，在场泡泡数和剩余行动值随各自操作独立变化。
- AI 在统一决策时刻获得对应逻辑时间的观察；收集动作时逻辑时间冻结。处理轮内事件不增加 AI 的决策机会。
- 首版速度限定整数格/tick，统一初始值为 1 格/tick，首期移速道具可增加 1 格/tick。按本轮固定速度移动时，存活且未遇阻在中心结束，遇阻也在中心截停，下一轮可重新选择方向；本轮拾取的道具从下一轮生效，不改变当前轮计划；旧轮终点仍用旧属性。
- 未收齐未判掉线的存活参与者的有效动作时继续等待，整局保持冻结，不因迟交自动代走或淘汰。只在连接明确关闭或发生连接错误时判掉线，不加心跳超时检测，不支持重连恢复。等待时在当前逻辑时刻处理掉线出局，模拟时在下一个内部结算点合并掉线与同刻受击淘汰后检查胜负。首次有效提交锁定，本轮不再接受该玩家查询或替换；动作重发只确认原计划，不重复执行。
- 轮初固定本轮方向和按速度决定的计划距离，途中不主动改向或停止；允许整轮原地等待。在中心检查下一格，遇到墙、箱子或泡泡阻挡则停在当前中心并终止本轮剩余移动；障碍消失也不自动重启。
- 泡泡阻挡新发起的进入。生成时已经在该格的所有玩家可离开，离开后不能重新进入；已开始的一格移动允许完成，即使目标格途中新放泡泡，到达后也可离开。
- 同格允许多颗泡泡，每颗分别记录归属、放置时刻和预定到期；范围按所属玩家当轮已生效属性计算；容量按玩家同时在场的颗数计算。同格一颗爆炸会立即连锁其余泡泡，每颗按自己的范围产生覆盖并释放所属玩家容量。
- 每个玩家每轮在每个中心最多请求一颗；同格叠放可来自不同玩家或不同轮次，不允许重复中心请求在同轮一次放多颗。
- 当次放置失败不取消移动或后续放置，并反馈失败原因。多个玩家同刻放同格不因占格竞争而失败，仍分别检查自身容量等条件。
- 每颗泡泡记录实际放置时刻 p 和固定寿命 L，预定到期为 p+L，不因同轮放置而自动统一到期。
- 固定寿命初始值已确认 L=3T，即三个逻辑 tick，不按现实等待时间计时。未获得移速增益的初始配置下，正常中心放置的到期在边界，但仍保留对应途中时刻引爆的模型能力。
- 泡泡可在决策周期途中对应的到期时刻引爆，不向轮末或固定模拟步边界推迟。
- 连锁可以使泡泡早于其预定到期引爆。已经引爆的泡泡不能在原预定时刻再次引爆。
- 引爆时按玩家中心所在格受击，移动不到半程归起点格，达到半程归目标格；受击直接淘汰，取消后续移动和动作。没有持续伤害区。
- 玩家互不阻挡、允许同格；首期包含三种道具：移速 +1 格/tick、同时在场泡泡容量 +1 颗、每方向爆炸范围 +1 格。不包含困泡救援和复活。统一初始属性不变：道具按配置数量开局预藏箱子，中心拾取，同刻到达者都获得；旧轮终点完成后下一轮生效，持续到局末且无上限，已放泡泡也使用实际爆炸轮的已生效范围。
- 爆炸遇硬墙不覆盖且停止；遇箱子覆盖、销毁并停止；遇其他格泡泡触发连锁，原射线按剩余范围继续传播。
- 同刻所有到期与连锁按爆炸开始前的同一份地图计算，算完再统一移除箱子和已爆炸泡泡。
- 先完成旧轮终点事件，再生成下一轮观察并冻结快照。下一轮从同一逻辑时刻开始，旧事件不重复执行。
- AI 采用以角色中心所属格为中心的方形局部视野，横纵距离各不超过 R；初始 R=2，最大 5×5，墙、箱子不遮挡，地图边缘裁剪。地形和实体只显示视野内，视野外未知；固定 21×21 布局已生成，玩家每局随机分配四角并保存种子。
- 免费泡泡观察提供视野内位置和本轮局部查询编号，编号本轮固定、下轮重分配。所有泡泡（包括自己的）详情按颗统一收费，每次成功都扣费，包括重复查询和同 requestId 网络重发；失败不扣费、不返回详情。行动值只用于查询，每轮重置不累积，移动和放置不消耗。
- 自身玩家状态全部免费，包括位置、速度、容量上限、当前在场泡泡数和剩余行动值。视野内其他玩家免费提供位置和跨轮稳定编号；付费详情返回身份（即该编号）、速度、泡泡容量上限、当前在场泡泡数，不返回剩余行动值。初始单价：每颗泡泡详情 1 点，每位其他玩家详情 2 点。
- AI 客户端是独立决策器，只与服务端交互观察、额外信息查询和 tick 决策，不参与 UI。服务端负责模拟，附带浏览器 UI 展示模拟过程；UI 展示与 AI 决策协议相互独立。
- 技术组合已确认：普通 C# 模拟核心，采用 .NET 10 LTS（net10.0），由一个 ASP.NET Core 服务端进程承载 AI 接口与 UI 后端并提供页面资源；浏览器使用原生 TypeScript＋Canvas 2D＋HTML/CSS。AI 接入采用原生 WebSocket＋JSON，每名 AI 一条参赛长连接承载观察、查询与动作；不加心跳超时检测，不支持重连。UI 使用独立 WebSocket＋JSON 传输全局状态、事件和运行控制，HTTP 提供 UI 资源及回放读取；关闭 UI 不导致 AI 出局。具体设计见 [首版系统架构设计](系统架构设计_首版.md)。
- 首版以 Windows 本机运行与验收，在本机运行服务端和浏览器 UI、验证 AI 接口；每个服务端进程同时运行 1 局，可在结束后连续开始下一局，每局 4 名 AI。AI 算法客户端仍暂不实现。性能通过验证程序运行后评估。
- 首版采用按轮组织有序请求的 JSON 预设脚本，创建时加载并校验结构，通过服务端同一套信息、扣费、校验、锁定与模拟规则执行。在 UI 选择脚本、可选指定种子并手动开始；结束后保留结果，下一局手动开始。脚本不包含策略算法，手动逐轮输入不列为必做。对局仍进行但一轮脚本执行完仍缺存活玩家有效计划时，结束验证、标记未完成，保留现场与记录，不判竞技输赢；正式 AI 未提交仍继续等待。具体脚本字段待设计。
- 首版浏览器 UI 展示全局游戏状态与事件日志，包括全图、所有玩家状态、泡泡详情及模拟事件，用于观察游戏进行和评估 AI。首版不加入单个 AI 的分析面板，AI 详细分析通过对局记录查看。UI 展示不受局部视野与付费查询限制；AI 决策协议仍按已确认的信息限制执行。提供暂停／继续和按 tick 单步控制服务端模拟：暂停在 tick 边界生效，单步须收齐所有存活玩家的有效计划，推进最多一个 tick 后暂停；途中触发胜负则立即结束。播放节奏与积压处理已确认，具体布局在实施时完善。
- 游戏数值采用 JSON 配置，每局创建时读取并固定，进行中修改仅影响之后新局，本局实际配置写入记录。服务端本地目录每局一个 JSONL 文件，进行中逐条追加，结束保留；记录地图、种子、AI 观察／查询／决策、模拟事件及掉线时刻，包含查询结果与扣费。
- 配置读不到、JSON 错误或参数不合法时，拒绝新局并在 UI 报原因，修正后重试，不回退默认值或旧配置。
- 回放读取记录，不重新请求 AI 决策或按新网络顺序裁决。首版固定 1 倍速，基准初始 1 秒／逻辑 tick，支持播放／暂停、前后逐 tick 查看和跳转。未完成记录可回放已保存的完整有效前缀，显著标未完成，不补模拟或推断缺失胜负。字段与目录待设计。
- 首版优先实时观战，服务端最小 tick 推进间隔初始为 1 秒，可配置；按相邻两轮实际开始模拟的现实时间计时。首轮收齐有效计划且允许运行即可开始，后续还须满足上一轮实际开始后的间隔，不等待 UI 完播回执。AI 未提交仍继续等待，实际间隔可更长，不因间隔已到补动作或淘汰；运行节奏不改变逻辑时间与游戏规则，也不要求计算一轮耗时 1 秒。
- 正常动画与回放 1 倍速基准初始为 1 秒／逻辑 tick，与服务端最小推进间隔独立配置。实时 UI 只计已模拟完成、尚未开始播放的轮，当前播放轮不计入，不按消息或事件数计数；积压达到 2 轮时追赶最新完整全局状态，阈值可配置。跳过积压动画但保留完整日志与记录，可回放查看，不因此暂停服务端，运行控制作用于当前服务端对局。
- 首版每局 4 人自由混战，每批同刻淘汰后立即检查：剩一人获胜，零人平局，立即停止模拟。淘汰者已放泡泡保留、继续计时，未执行计划取消；对局结束后不再推进。最大 tick 初始上限为 500，到上限仍多人存活则平局。

## 时间与实现建议

用 T 表示统一 AI 决策周期，T=1 个抽象逻辑单位，用 t 表示事件时刻。内部已确认使用分数 tick 精确运算和比较，支持 1/3、1/2 等途中时刻，显示可转小数，舍入不参与裁决。寿命初始 3 tick、速度初始 1 格/tick。对外时间采用分子、分母整数对象，例如 {"numerator":1,"denominator":3} 表示 1/3 tick；整数 3 tick 表示为 {"numerator":3,"denominator":1}。观战播放时长单独配置。

推荐按事件时刻分段推进：找出下一次到期、中心到达、阻挡或已获准计划动作等事件，把所有玩家推进到该时刻，统一裁决后继续。这里是实现建议；用户确认的是途中准确计时规则，不是指定某种队列数据结构。

事件驱动不要求 AI 在每个事件时刻重新决策。本轮整数格移动方向和沿途可选放置位置在首次有效提交时锁定，不允许途中改向或停止；整轮等待已确认，等待一段时间后再启动不作为已确认能力。动作放置位置采用格子坐标对象列表，其他序列化字段在实施时完善。更新后的规则不要求将 T 分成固定 N 个小步才能表达 T/3 到期。

## 同一时刻的主要结算顺序

沿用已确认顺序：

1. 得到所有玩家该时刻的合法位置与进度；路径扫描先处理沿途约定阻挡。
2. 处理该结算点的待处理掉线，取消掉线者未执行计划；其已放泡泡仍保留。按该时刻爆炸前的同一份地图计算所有到期泡泡与连锁，形成总覆盖；每颗只引爆一次，计算完成后统一移除已爆炸泡泡和被毁箱子。
3. 销毁爆炸覆盖内原有露出道具，释放被毁箱子中预分配道具，新掉落者保留。按同刻位置判定受击，合并掉线与受击淘汰，取消淘汰者后续移动和动作。
4. 检查剩余玩家：一人获胜、零人平局，立即结束，不执行后续步骤；多人则继续。
5. 对存活中心到达者批量拾取道具，同刻到达者都获得增益，累计到下一轮再生效；随后统一执行放置，按当轮已生效容量判定成败。
6. 全部放置处理完毕后，检查下一格阻挡并启动新的移动段；遇阻则在当前中心终止本轮移动。已经提前开始的一格移动保留完成许可。
7. 根据新的环境与动作继续推进。

恰好到达安全格可以避开爆炸；该时刻才开始的移动不能改变引爆时刻位置。到中心放置与旧泡泡到期同时发生时，先爆炸和淘汰，存活者才可放置。

传播、销毁快照与观察时机已确认。旧轮终点的到期、淘汰、拾取及终点放置全部完成后，统一激活道具增益，再生成观察，收集下一轮计划；下一轮从同一时刻开始，已结算事件不重复执行。旧轮终点已没有剩余移动预算，不额外启动旧计划的新移动段。

## 已确认的爆炸传播与快照

- 硬墙格不计入危险覆盖，射线在墙前停止。
- 箱子格计入覆盖并被销毁，射线在箱子格停止。
- 另一格泡泡计入覆盖并触发连锁；原射线继续按剩余范围传播，不因泡泡停止或额外延长。
- 同格所有泡泡同时连锁，每颗按自身范围产生覆盖；一颗不会被多个来源重复引爆或重复释放容量。
- 全部同刻到期与递归连锁使用同一份爆炸前地图。因此同刻一颗炸毁箱子，不会让另一颗的射线穿过该箱子。
- 算完该批总覆盖后，统一移除已爆炸泡泡和被毁箱子、处理受击；随后放置和新段阻挡检查使用更新后的环境。此前已经因阻挡终止本轮移动的玩家不会自动重启。

例如 A1 泡泡向右范围三格，B1 有另一泡泡，C1 有箱子：原射线覆盖 B1 并触发连锁，继续覆盖 C1、销毁箱子，但停在 C1，不覆盖 D1。其他同刻爆炸也不能因 C1 已被标记销毁而穿过它。

## 已确认的局部观察

以观察时刻玩家中心所属格 (cx,cy) 为中心，格 (x,y) 满足 |x-cx|≤R 且 |y-cy|≤R 则在方形视野内，再裁剪地图边界。硬墙和箱子不遮挡，受击所在格的半程归属规则也用于确定视野中心格。

地形和实体均只显示视野内，视野外未知。观察只发送视野内格子的坐标与地形及视野内实体列表，不发送完整地图矩阵；未发送格子视为本轮未知，不代表空地。客户端可以自行保留历史记忆。每颗可见泡泡免费提供位置和本轮局部查询编号，同格多颗分别编号；归属、范围和准确预定到期需要消耗行动值查询，包括自己的泡泡。自身玩家状态免费，其他可见玩家位置和跨轮稳定编号免费，四项详情收费。身份就是稳定编号，R 初始值为 2。内部事件不向 AI 新增实时观察；查询不得读取正在推进的后续状态。

### 行动值查询流程

旧轮终点结算 → 激活待生效道具增益 → 恢复行动值、冻结快照、下发免费局部观察 → 客户端查询详情 → 首次有效提交锁定并关闭该玩家本轮查询 → 等待所有存活参与者提交 → 统一推进本轮。

动作计划包含非法方向或路径外放置位置时，整份拒绝并返回原因，不锁定本轮，允许修正重交，不执行任何有效子部分。合法方向遇到实际阻挡仍按截停处理；执行时容量不足仍只失败当次放置请求。具体错误反馈字段待协议定义。

未判掉线的玩家未提交时保持逻辑时间冻结，不因现实等待自动开新轮、恢复额度、推进移动或泡泡计时。首版不支持重连，只在连接明确关闭或发生连接错误时判掉线，不加心跳超时检测。等待时在当前逻辑时刻处理出局并检查胜负；模拟时在下一个内部结算点先推进位置，取消掉线者未执行计划，再结算爆炸，合并掉线与受击淘汰后检查胜负，结束则不再放置或移动。出局后不再等待其计划，已放泡泡按淘汰者规则保留。动作迟交、查询失败或无效动作不属于连接错误。若网络中断但服务端尚未收到关闭或错误通知，仍可能继续等待。等待提示尚待定。

等待期间掉线且对局仍继续时，通知剩余玩家掉线者的稳定编号，保留原观察和已查询结果，不重开决策轮、不重置行动值、不撤销已锁定计划。掉线玩家不再可查询，失败不扣费；未提交者继续查询和提交，已提交者的查询仍关闭。已放泡泡保留，视野内泡泡仍使用本轮原编号和快照。掉线通知不额外披露位置或其他隐藏场景详情。

查询使用本轮同一快照，游戏时间保持冻结；预定到期仍可能被连锁提前。只查询消耗行动值、按颗购买完整详情、每轮重置且不累积；初始单价泡泡 1 点、其他玩家 2 点，每轮初始额度 10 点。当前方案不授权查询视野外实体，也不授权等待后再移动或途中改向。

每次成功查询都扣费，主动重复和同 requestId 网络重发都扣费；失败不扣费、不返回详情，现实耗时仍可统计，但不会因超时自动补动作或淘汰。局部编号仅在本轮快照内有效，gameId、roundId 用于关联正确对局和本轮快照，不要求新增已确认之外的快照标识字段。动作与查询不同：首次有效计划锁定，动作重发只确认、不重复执行。提交后查询不再接受，因此迟到查询不成功、不扣费。

客户端可以记忆和推断；例如已知自身实际放置时刻与固定寿命时，可以推算自己的泡泡预定到期。自身在场泡泡数可能因视野外爆炸而变化，这是免费自身状态的一部分。自己的泡泡详情仍统一收费，自行推断不需要向服务端付费。

自身剩余行动值随查询更新并免费反馈，游戏逻辑时间保持冻结。其他玩家付费详情对应轮初冻结状态，返回身份、速度、泡泡容量上限、当前在场泡泡数，不返回其剩余行动值。身份已确认就是免费稳定编号，响应重复附带它用于关联，不新增参赛名称等信息。即使以前见过编号，该玩家不在当前视野也不能查询其当前位置或详情；在场泡泡数包含其视野外泡泡，但不披露那些泡泡的位置。

## A1 向右三格并沿途放置

演示使用 5×5 地图，列 A 至 E、行 1 至 5，其余格子为空。玩家从 A1 中心匀速移动到 D1，速度为三格/T。本例用户已明确不在 A1 放置，而在到达 B1、C1、D1 中心时各放一颗；初始没有该玩家的泡泡，同时在场容量为三颗。

这些速度、容量和地图仅为历史时间模型演示，不是首版配置；当前首版速度已确认 1 格/tick，本例仍以三格/T 说明模型可表达的时间关系。以下时间以途中存活、放置均合法为前提。

| 泡泡位置 | 实际放置时刻 | 预定到期 |
| --- | --- | --- |
| B1 | T/3 | T/3+L |
| C1 | 2T/3 | 2T/3+L |
| D1 | T | T+L |

每颗预定到期独立计算。容量三限制同时在场数量，不自动限制每轮放置请求的总次数。若寿命短到前一颗途中爆炸，可能发生提前淘汰或容量释放，应按实际事件推进，不能先假定整轮三颗全部放置成功。

仅为展示连锁，取 L=T，每颗范围一格，沿途无阻挡：B1 原定 4T/3 到期，C1 原定 5T/3，D1 原定 2T。到 4T/3 时三颗均已放置；B1 爆炸触发 C1，C1 再触发 D1，三颗在 4T/3 实际引爆。L=T 和范围一格不是新确认的正式参数。

## 原 A1 与 B2 引爆案例

玩家从 A1 中心匀速向右三格，B2 范围一格覆盖 B1。引爆在 0 时玩家 A1 存活；引爆在 T/3 时玩家在 B1，淘汰；引爆在 T 时玩家已到 D1，存活。T/3 不再需要对齐固定小步边界。

沿途检查仍不能省略：高速移动不能只检查终点是否可通行。已确认在中心开始下一段前检查阻挡，遇阻终止本轮剩余移动；已开始的一格移动不因目标格新放泡泡而中断。

## 已确认的泡泡阻挡例外与截停

- 生成时已经在泡泡格的所有玩家均可离开，离开后不能重新进入仍存在的该泡泡格。
- 已经开始 A1→B1 的一格移动后，B1 新增泡泡，允许该段完成，到达者随后可以离开；泡泡阻止后来新发起的进入。
- 在格子中心开始下一段前检查阻挡；发现阻挡就停在当前中心并终止本轮剩余移动。障碍稍后消失也不自动重启，未到达位置的放置请求不执行。
- 离开许可针对玩家和具体泡泡，离开或泡泡消失后失效；不表示该格永久可通行。截停中心的已选放置请求仍须按正常条件检查，只有未到达位置不能执行。

以上为完整首版规则；M0 已实现当前泡泡格离开和基础阻挡，途中新增泡泡等一般情形尚未实现。同刻先统一放置，再检查阻挡并启动新段；例如甲刚到 B1、乙同刻在 C1 放泡泡，甲会被挡在 B1。若甲早已开始 B1→C1，则可完成该段并随后离开。

同格可有多颗泡泡，已有泡泡不会使新放置仅因占格而失败；但该格仍阻挡没有相应许可的新进入。多个玩家同格各放一颗时，各自容量各增加一颗。每颗独立计时，同格一颗引爆立即连锁其余泡泡；每个玩家每轮每中心最多请求一颗。
