# 对战协议逐项确认记录

更新日期：2026-10-18。信息和动作规则沿用讨论确认；登记、淘汰、结束及错误码采用下文记录的实现格式。功能已实现并按既定方案验收，结果见 [运行与验收记录](对战运行与验收记录.md)。总体流程见 [实施计划](对战流程实施计划.md)，规则依据见 [已确认规则](../首版模拟规则_已确认版.md)。

统一配置补充：下文 10 点额度、1／2／3 点查询费用和 500 tick 是默认值，现由文件配置并冻结到本局；以成功登记返回的 `rules` 为准。入口、覆盖顺序和字段见 [统一配置说明](../config/服务端配置说明.md)。

## 已确认：观察划分

- `self`：当前玩家完整游戏状态。
- `participantIds`：视野外其他玩家的稳定唯一编号，不含自身。
- `visible.players`：视野内其他玩家编号与位置，不含自身；与 participantIds 不重复，每轮按冻结状态重新划分。
- `visible.cells`：可见格子坐标与地形。
- `visible.bubbles`：可见泡泡位置与本轮局部 queryId，同格多颗独立编号；不免费披露详情。
- `visible.items`：可见已露出道具的位置、类型与效果；不发送箱内隐藏内容。
- 首轮起始逻辑时刻为 0，决策轮编号从 1 开始。逐帧模式点击后才开启决策轮并下发观察。

## 已确认：玩家查询

| 目标 | 每次成功费用 | 返回信息 |
| --- | --- | --- |
| 视野内其他玩家 | 2 点 | 唯一编号、位置、速度、泡泡容量上限、泡泡火力、视野宽度、在场泡泡数 |
| 视野外其他玩家 | 3 点 | 与视野内相同，包含位置 |

详情及视野内外判定读取本轮同一冻结状态。自身状态免费。仍沿用每轮 10 点额度、成功重复查询再次扣费、失败不扣费且不返回详情、首次有效提交后关闭本轮查询，以及等待阶段掉线目标禁用规则。

七项字段名为 `playerId`、`position`、`speed`、`bubbleCapacity`、`blastRange`、`visionWidth`、`activeBubbleCount`。火力对应每方向爆炸范围；视野宽度用未裁剪方形边长 2R+1 表示，地图边缘裁剪不改变该属性，例如 R=2 时 visionWidth=5。

## 已确认：查询请求与回复

外层使用 type、gameId、roundId、requestId、payload；服务端主动推送不带 requestId，登记不要求 roundId。查询与提交的操作者从连接身份取得，不由 payload 指定。

`query.request` 一次查询一个目标，payload 为 targetType（bubble／player）和 targetId；泡泡引用本轮 queryId，玩家引用稳定 playerId。

`query.result` 原样带回请求的 gameId、roundId、requestId；payload 包含 targetType、targetId、success、cost、actionPoints、data、error。

- 成功：success=true，cost 为实际扣费，actionPoints 为处理后自身剩余行动值，data 为详情，error=null。
- 失败：success=false，cost=0，actionPoints 为处理后自身剩余行动值，data=null，error 为含 code、message 的对象。错误码见下文。

## 已确认：泡泡查询详情

泡泡仅限本轮视野内目标，自己的泡泡同样收费，每次成功 1 点。data 包含 ownerId（所属玩家编号）、blastRange（本轮已生效每方向爆炸范围）、dueAt（分子／分母对象编码的预定到期绝对逻辑时刻）。位置及 queryId 已在免费观察与请求关联中提供，不重复增加付费字段。

详情读取本轮冻结状态。连锁可能使泡泡早于 dueAt 爆炸，后续道具增益可能改变实际爆炸范围。

## 已确认：决策上报与回复

`action.submit` 的 payload 两项必填：direction（wait／up／down／left／right）和 placements（格子坐标对象列表）。不填移动距离，采用本轮已生效速度；等待仍可在当前格放置，空列表表示不放置。同轮同中心最多一颗，重复、越界或名义路径外坐标整份拒绝。按实际到达中心时刻放置，列表顺序不决定执行时间；实际阻挡与执行时容量不足不使几何合法计划变成非法提交。

`action.result` 原样带回关联字段，payload 包含 success、locked、plan、error：

- 首次有效提交：success=true、locked=true、plan 为锁定计划、error=null，关闭本轮查询。
- 首次提交非法：success=false、locked=false、plan=null、error 为 code／message，允许修正重交。
- 本轮已经锁定后再次提交：success=true、locked=true，返回原锁定计划，不替换、不重复执行。
- 错局、错轮或阶段不允许提交：拒绝并返回原因，不锁定新的计划。错误码见下文。

锁定表示计划接受，不保证移动／放置实际成功；阻挡、容量、淘汰与终局仍由模拟裁决。

## 实现补齐：生命周期协议

| type | payload | 条件与含义 |
| --- | --- | --- |
| `register.request` | `{}` | 携带gameId和字符串requestId，不要求roundId；准备阶段申请席位 |
| `register.result` | `success, playerId, playerCount, rules, error` | 成功返回绑定编号、实际人数与本局公开规则；失败只返回success=false和error；原样关联请求 |
| `round.started` | `time, self, participantIds, visible` | 每个决策轮唯一的免费观察；无requestId |
| `participant.eliminated` | `playerId, time, reason` | reason为disconnected／explosion；通知只含编号及淘汰时刻，不免费暴露位置 |
| `match.ended` | `winnerId, time, reason` | winnerId为唯一胜者或null；reason为elimination／tickLimit；固定结果后通知，发送完成再关闭AI连接 |

登记暂定名 `participant.register／participant.registered` 在实现中统一为 `register.request／register.result`。这只补齐命名，不改变绑定身份、补位与开局条件。服务器为本局分配编号1..N，跨轮稳定；不同对局的gameId不同。开局后拒绝补位。

成功登记的 `rules` 为 `{maxTicks, actionPoints, bubbleCost, visiblePlayerCost, outsidePlayerCost}`，均为整数。maxTicks 为正，其余非负；允许零费用，非法目标仍失败。本轮剩余额度以 self.actionPoints／query.result.actionPoints 为准。公开规则不包含隐藏道具、完整地图或其他玩家信息。

`self` 实际字段：`playerId, position, speed, bubbleCapacity, activeBubbleCount, blastRange, bubbleLifetime, visionRadius, actionPoints`。寿命和时间使用 `{numerator,denominator}` 的精确分数对象；position为整数坐标对象。观察中的其他玩家列表只包含本轮开始时仍存活者，排除自身；有人在等待阶段掉线时，已经发送的观察保持不变，玩家查询返回targetEliminated，遗留泡泡仍按原queryId查询。下一轮不再列出淘汰者。

查询和提交必须带有效的字符串requestId以及gameId／roundId；成功重复查询仍扣费，requestId不作为免费去重凭据。一般消息结构错误使用 `type=error,payload.error={code,message}`，可处理的查询／计划拒绝使用各自result。生命周期通知以gameId和精确time为准；未模拟任何tick时终局roundId可为0。

## 实现补齐：UI 控制与状态

UI通道接收下列命令，AI通道不接受这些命令：

- `match.create`：payload可含playerCount、manualTickAdvance、seed、initial、items，省略时继承选定配置文件。initial／items整块覆盖，显式null分别恢复正式地图／关闭文件道具；seed:null表示强制随机，不继承文件种子。这不是AI可写接口。
- `start`：携带gameId；必须人数齐且尚未开局。
- `tick.demonstrate`：携带gameId和待开启roundId；仅逐帧AwaitingTick阶段生效，不积攒点击许可。
- `match.abort`：携带gameId；先固定未完成／中止状态，再做验证失败清理，不以清理制造胜负。

`session.state` 的payload含phase、playerCount、registeredCount、manualTickAdvance、seed、nextRoundId、canStart、canDemonstrate和waitingPlayerIds。phase取idle／preparing／awaitingTick／collecting／simulating／ended／aborted。全局 `frame` 沿用现有地图、属性、精确事件和动画格式；观战完整信息不通过AI观察发送。

配置迭代新增 `session.state.payload.defaults={playerCount,manualTickAdvance,seed}`，其中seed可为null，供UI初始化控件；UI未修改的字段省略覆盖。frame新增 `catchUpThreshold`、`playbackSpeed`，分别控制待播轮追赶和动画倍率，不改变服务端模拟。durationMs仍为缩放前基准时长。

## 错误码

| 错误码 | 含义 |
| --- | --- |
| wrongGame／wrongRound | 对局或轮次不匹配 |
| notRegistered／eliminated | 未登记或操作者已经淘汰 |
| wrongStage | 当前阶段不接受该操作或演示命令已过期 |
| invalidTargetType／invalidTarget | 查询类型／目标编号不合法（含查询自身玩家详情） |
| targetEliminated | 玩家目标已淘汰 |
| insufficientActionPoints | 本轮余额不足 |
| planLocked | 首次有效计划后关闭查询 |
| invalidPlan | 整份计划的方向、坐标、数量、重复或名义路径非法；仍可修正 |
| notPreparing／alreadyRegistered／roomFull | 登记时不在准备阶段、连接已绑定或席位已满 |
| notReady | 人数不足或已开局，不能再次开始 |
| invalidRequest／unknownType | 消息结构／字段错误或消息类型未知 |

查询失败cost=0、data=null，不改变余额；提交失败不锁定新计划。同一阶段不同错误的优先级不作为玩法承诺，例如先检查错局／错轮，再检查目标和余额；调用方按code处理，不依赖message文字。
