## 运行

在仓库根目录执行：

```powershell
npm.cmd run build:ui
dotnet run --project src/QQT.Server -- --battle
```

打开 `http://127.0.0.1:5080`，选择 2／3／4 人、逐帧开关和可选种子，创建对局。种子留空由服务端随机生成；指定种子用于重现出生分配。满员后点击“开始对战”；逐帧模式首轮及后续各轮均点击“tick演示”。未开启逐帧时自动收集、模拟、开启下一轮。

`appsettings.json` 提供 `Match.PlayerCount=4`、`Match.ManualTickAdvance=false` 的服务端默认值，创建请求可覆盖并固定本局配置。`Scenario.TickIntervalMilliseconds=1000` 控制最小模拟开始间隔，`AnimationMilliseconds` 独立控制 UI 动画。竞技上限固定 500 tick，独立于旧脚本容量上限。旧 `--verify --script <路径>` 和不带 `--battle` 的本地脚本模式保留。

AI 使用 `/ws/ai`，UI 使用 `/ws/ui`。登记需要本局 gameId，由创建后的 UI 通道 `session.state.gameId` 提供；服务器也记录 gameId 和实际出生分配。每个参赛连接绑定一个 playerId，终局通知发送完成后关闭 AI 连接，新局重新连接登记。

脚本客户端项目 `src/QQT.ScriptClient` 只解释输入命令流 `send`／`close`／`stop`，不实现 AI。运行器从 `scripts/battle/` 的固定脚本发送请求并核对预期；泡泡编号只绑定脚本指定位置对应的可见 queryId，全局帧只用于验收断言。

## 一条验收入口

```powershell
./scripts/verification/verify-battle.ps1
```

默认先构建，再依次运行两人最小联机、三人信息／锁定（两种模式）、四人九轮完整比赛（两种模式）、生命周期参数场景、500 轮上限、同刻网络断线检查、既有核心回归、真实浏览器验收。输出默认位于 `artifacts/battle-<时间>/`；`-Output` 可指定目录。`-SkipBuild` 复用已构建程序；`-SkipBrowser` 只用于单独排查，汇总会明确标记验收不完整。失败返回非零并停止后续步骤，保存首个差异后先中止对局，再清理连接。

浏览器验收使用 Playwright 驱动本机 Chrome 的独立临时会话；可用 `QQT_CHROME` 指定现有 Chrome 路径。Playwright 优先读取项目环境，其次读取 Codex 已捆绑依赖；不在验收中下载或安装浏览器。此次浏览器控制工具因 Windows 沙箱初始化失败，改用现有 Chrome 的 headless 模式，实际加载页面、点击按钮、播放动画并保存完整截图，没有将 WebSocket 核对当作浏览器验收。

## 实现边界与记录

`BattleCoordinator` 的单一读取者修改对局，模拟按完整同刻批次推进；接收线程仅排队命令。每个连接有独立有界发送队列，消息缓冲在发送结束后归还池；队列无法维持时关闭连接，参赛连接关闭按既定掉线规则裁决。等待决策没有现实超时。

每轮先激活属性、重置10点预算，捕获独立观察及付费详情。等待按钮不准备下一轮；等待期间掉线不推进时间、不重置他人的预算或锁定。新轮名单只包含存活的其他玩家；既有冻结观察不因掉线改写，目标查询会明确拒绝已淘汰玩家。

默认每局记录 `artifacts/battle/<gameId>.jsonl`，`Battle.RecordDirectory` 可覆盖。记录包含原始配置、实际种子／出生映射、绑定身份的请求与回复、UI控制和状态、逐条核心事件及展示帧；没有 UI 订阅也保存模拟事件。记录写入失败停止后续推进并保留中止现场，不尝试通过重放查询恢复预算。

所有新增业务容器缓冲使用已有对象池／数组池；最大容量和有效人数分开。冻结观察、锁定计划和发送内存有明确所有者；宿主等待结束后归还，重置清理借用引用，Dispose 防止重复归还。不声称框架内部分配已被消除。
