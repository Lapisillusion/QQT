## 实现与验收预期

- 同刻所有自然到期泡泡先入队；覆盖未入队泡泡时追加连锁。入队时标记，每颗最多一次，包含同格叠放与相互覆盖。
- 原泡泡射线穿过被触发泡泡后按剩余范围继续，不延长射程。硬墙不覆盖并停止，箱子覆盖并停止。整批队列消费完才统一移除箱子和泡泡，之后统一受击淘汰并检查胜负。
- 剩一人立即获胜，零人立即平局；结束后取消后续放置，脚本运行器不进入下一轮，核心也拒绝结束后的直接推进。500 tick 上限尚未实现。
- 队列、去重标记和覆盖掩码使用数组池，唯一所有者为本次爆炸结算，异常路径通过 finally 归还；泡泡与地形只在覆盖完成后修改。输出仍通过独立消息缓冲发送，结束现场未被提前清理。
- `expected.end` 声明结束时刻／胜者；泡泡 `dueAt` 声明原定到期，`explodedAt: null` 声明现场遗留，`sourceBubbleId` 声明连锁来源。验证器检查唯一放置／爆炸、实际时间、归属、逐格地图、结束事件次数与顺序；原脚本格式兼容。

## 复现

从仓库根运行：

```powershell
npm.cmd run build:ui
dotnet build QQT.sln
dotnet src/QQT.Server/bin/Debug/net10.0/QQT.Server.dll --verify --script scripts/m0-chain-victory.json
dotnet run --project src/QQT.Core.Checks/QQT.Core.Checks.csproj -- E:/Project/Codex/QQT/scripts/m0-chain-victory.json
```

展示页面时使用上一程序集命令去掉 `--verify`，打开 http://127.0.0.1:5080。核心检查的脚本参数需要绝对路径；其他机器按实际仓库目录修改。

本环境 RTK 不可用，常规沙箱进程无法启动，编辑工具亦不能读取工作区重解析路径。已如实使用获准的项目目录访问执行原生命令；未声称通过 RTK。仓库没有 `.codegraph/`，按规范跳过。
