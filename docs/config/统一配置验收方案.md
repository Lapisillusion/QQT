# 统一配置验收方案

2026-10-18。本轮只验证配置入口、参数落地和受改动影响的既有路径。先记录输入和预期，再实际运行；不增加 AI 对抗场次。

| 输入 | 预期 |
| --- | --- |
| 默认配置启动旧脚本及原统一对战验收 | 原有位置、爆炸、扣费、生命周期、终局及浏览器断言继续通过 |
| `--config` 指向独立子目录文件；脚本与记录目录写相对路径 | 不合并默认 JSON，路径以该配置目录解析；旧脚本可以正常验收，记录位于指定子目录 |
| 缺失文件、残缺配置、负查询费、零寿命、随机道具负数量 | 明确失败；错误不被默认 appsettings 或环境变量掩盖 |
| 文件默认 3 人、逐帧、出生 seed=42；速度2、容量4、范围2、视野3、寿命5/2；额度7、费用2/3/4；上限2 tick | 空建局请求完整继承。首轮观察属性一致；同一泡泡查两次余额7→5→3，再查可见玩家至0；不足拒绝不扣费。另一玩家查视野外玩家扣4并返回正确位置；两轮等待后 t=2 多人存活判上限平局，无第3轮 |
| 文件内 fixed 道具；建局省略 items | 道具预藏于指定箱子；UI 全局分配记录正确，AI 不会免费看到箱内道具 |
| 首局创建后修改文件为2人、速度3、额度9、上限1、无道具 | 首局继续使用旧快照。下一局使用新人数、属性、预算和上限，t=1 上限平局 |
| 终局后损坏配置，或把记录目录指向既有文件后尝试创建 | 返回配置错误，保留已完成对局与结束阶段；修复后能够再建局 |
| 请求显式覆盖人数、逐帧、seed、initial、items | 覆盖仅影响该局，items 是整块替换；显式 null 可关闭文件道具，空请求仍继承文件 |
| 查询费用设为0 | 可见有效泡泡查询成功且余额不变；非法编号仍拒绝，不能把零费用当成无效目标 |
| 文件出生seed=42，建局恢复正式地图且省略seed | 两人出生准确为(0,0)、(0,20)，不使用代码内隐藏默认种子 |
| 浏览器使用文件默认人数／逐帧／seed | 控件初值来自服务端。未改控件时不发送覆盖字段；主动改控件时发送覆盖 |
| UI 动画积压与播放倍率 | 少于阈值的待播轮保留；达到阈值跳到最新完整帧；阈值只计待播、不计当前动画。播放倍率改变动画时长，不改变逻辑时间 |

自动入口：`python scripts/verification/configuration.py --output artifacts/configuration`。通过真实独立 C# ScriptClient 及 WebSocket 验证配置的实际行为；保存选用配置、服务端日志、客户端消息、JSONL 和报告。既有回归使用 `scripts/verification/verify-battle.ps1`，本轮新增配置检查也纳入该入口。

实际运行结果与证据目录见 [统一配置实施与验收记录](统一配置实施与验收记录.md)。
