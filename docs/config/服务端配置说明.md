# Server 统一配置说明

更新：2026-10-18。默认值集中在 [appsettings.json](../../src/QQT.Server/appsettings.json)。本次已统一配置加载、道具继承与参数生效；地图按确认保持 21×21。

## 1. 启动与唯一入口

```powershell
# 默认读取程序输出目录中的 appsettings.json
dotnet run --project src/QQT.Server -- --battle
# 使用完整替代配置
dotnet run --project src/QQT.Server -- --battle --config ./profiles/local.json
# 旧脚本使用同一配置入口
dotnet run --project src/QQT.Server -- --verify --config ./profiles/local.json
```

- `--config` 相对路径按启动工作目录解析。文件内所有相对路径统一按**选定配置文件目录**解析，包括 ScriptPath 和 RecordDirectory。
- 指定文件完整替代默认文件，不合并默认 JSON、环境文件或环境变量。默认文件损坏也不妨碍指定文件独立运行。
- 不指定路径时读取 AppContext.BaseDirectory 下的 appsettings.json。构建会复制源配置和脚本到输出目录；修改源默认文件需要重新构建，修改显式指定文件则无需复制。
- 缺文件、缺必填项、类型或范围错误均明确失败，不用隐藏默认值补齐。字段大小写按示例填写。
- 支持 `--battle`、`--verify`、`--config <路径>`、`--script <路径>`。battle 与 verify 互斥。保留的 --script 只显式覆盖旧脚本路径，其相对路径按启动工作目录解析；联机不执行脚本。
- 复制默认文件到新目录后需调整其中路径。例如 profiles/local.json 指向仓库脚本时，ScriptPath 应为 ../scripts/m0.json。

宿主使用 [CreateEmptyBuilder](https://learn.microsoft.com/en-us/dotnet/api/microsoft.aspnetcore.builder.webapplication.createemptybuilder?view=aspnetcore-10.0)，避免框架预先读取其他默认配置。

## 2. 生效时机与覆盖

| 配置 | 生效时机 |
| --- | --- |
| Urls、Logging、接收缓冲、消息池、出站队列、初始事件缓冲 | 进程启动，修改后重启 |
| Match、Player、Queries、Items、Initial、Ui、tick 间隔、动画时长、脚本路径／轮数限制、记录目录 | 每次联机建局或旧脚本重跑重新读取同一文件，冻结为本局快照 |

本局不会因文件修改中途变更。下次创建重新校验，非法配置拒绝建局并保留上一局结果，修复后可以继续创建。

联机优先级：**match.create.payload 显式字段 → 文件配置**。支持 playerCount、manualTickAdvance、seed、initial、items。initial/items 是整块替换；显式 null 分别恢复正式地图／关闭文件道具；seed:null 强制重新随机。只影响该局。

旧脚本顶层 items、initial 优先于文件对应块；显式 playerCount 决定实际人数，省略则使用 Match.PlayerCount。两种模式共用校验和初始化。未指定出生 seed 的旧脚本保留既有固定编号映射，联机则随机生成。

UI 初值来自服务端。未改动的控件省略覆盖字段，主动修改后才覆盖文件；满员只就绪，仍需 UI 手动开始。

## 4. 对局、属性、费用、展示和记录

| 键 | 默认值 | 类型、范围、用途 |
| --- | --- | --- |
| Urls | http://127.0.0.1:5080 | 非空监听地址字符串，多地址可用分号分隔；verify 不监听 |
| Match.PlayerCount | 4 | 整数 2／3／4 |
| Match.ManualTickAdvance | false | 布尔值，首轮和后续轮都在点击按钮后下发观察、收集计划并模拟最多一个 tick |
| Match.MaxTicks | 500 | 正 Int32，竞技上限；到达终点结算后仍多人则平局，不生成下一轮 |
| Match.Seed | null | 可选 Int32 或 null；四角出生分配种子，与道具 seed 独立 |
| Player.Speed | 1 | 正 Int32，格/tick |
| Player.BubbleCapacity | 3 | 正 Int32，同时在场泡泡上限 |
| Player.BlastRange | 1 | 正 Int32，每方向爆炸范围 |
| Player.VisionRadius | 2 | 非负 Int32，方形半径，宽度为 2R+1 |
| Player.BubbleLifetime | 3/1 | 正精确时间：整数或 {numerator,denominator}，分母为正，支持 5/2 等分数 |
| Queries.ActionPoints | 10 | 非负 Int32，每轮重置，移动与放置不消耗 |
| Queries.BubbleCost | 1 | 非负 Int32，成功查询可见泡泡的费用，自己的泡泡同价 |
| Queries.VisiblePlayerCost | 2 | 非负 Int32，成功查询视野内其他玩家的费用 |
| Queries.OutsidePlayerCost | 3 | 非负 Int32，成功查询视野外其他玩家的费用，仍返回位置 |
| Battle.RecordDirectory | artifacts/battle | 非空路径，相对配置目录；联机写入 `<gameId>.jsonl` |
| Ui.CatchUpThreshold | 2 | 正 Int32；待播完整轮达到阈值跳至最新完整帧，不计正在播放的一轮 |
| Ui.PlaybackSpeed | 1 | 有限正数；实时动画倍率，2 表示基准时长减半，不改变逻辑时间 |

成功登记的 register.result.payload.rules 公布 maxTicks、actionPoints、bubbleCost、visiblePlayerCost、outsidePlayerCost。客户端应读取本局规则，不能把默认费用当作协议常量；初始属性仍由 round.started.self 提供。

## 5. Scenario 执行与内存参数

| 键（位于 Scenario 下） | 默认值 | 校验与作用 |
| --- | --- | --- |
| ScriptPath | scripts/m0.json | 字符串路径，相对配置目录；--script 已提供时可省略；旧脚本每次运行重新读取，联机不执行 |
| TickIntervalMilliseconds | 1000 | 正 Int32 毫秒，相邻实际模拟开始的最小现实间隔；首轮不额外等待，verify 跳过现实节奏等待 |
| AnimationMilliseconds | 1000 | 正 Int32 毫秒／逻辑 tick，UI 基准动画时长，再按 PlaybackSpeed 缩放 |
| ReceiveBufferBytes | 4096 | Int32，64～65536，完整接收 JSON 文本容量，分片累加，UI／AI 共用；超限关闭连接 |
| MaxScriptTicks | 128 | 正 Int32，旧脚本 totalTicks 加载上限，与 Match.MaxTicks 是独立限制 |
| MessageBufferBytes | 16384 | 正 Int32 字节，出站池缓冲初始容量，不足自动扩容，不是发送硬上限 |
| MessagePoolRetained | 8 | 正 Int32，消息对象池最大保留数，不是玩家或连接上限 |
| OutgoingQueueCapacity | 64 | 正 Int32，每个联机连接出站队列容量，无法入队时关闭连接 |
| InitialEventCapacity | 96 | 正 Int32，事件／历史缓冲初始预留，不足从数组池扩容，不是事件上限 |

网络关闭后的淘汰规则不变。内存初始容量在启动确定，不会因下一局修改而缩减已复用的缓冲。AI 等待期间逻辑时间不增长，动画倍率和现实间隔不会重写泡泡计时。

## 6. Items：联机与旧脚本共用

省略 Items 或设 null 表示无道具。建局 payload.items／脚本 items 整块覆盖文件；没有覆盖则继承文件。固定与随机互斥，没有 mode=none。

| 字段 | 要求 |
| --- | --- |
| Items.mode | 必填小写 fixed／random |
| Items.seed | random 可选 Int32，省略则生成实际种子并记录；fixed 禁止 |
| Items.counts.speed | random 必填非负 Int32，移速道具数量 |
| Items.counts.capacity | random 必填非负 Int32，容量道具数量 |
| Items.counts.range | random 必填非负 Int32，火力道具数量 |
| Items.counts.vision | random 必填非负 Int32，视野道具数量 |
| Items.placements | fixed 必填数组，可空；random 禁止 |
| Items.placements[i].type | speed／capacity／range／vision |
| Items.placements[i].position | {x,y}，各为0～20，必须位于不同的初始箱子 |

fixed 禁止 counts。random 四类计数须齐全，不能为负，不接受未知类型；需求大于箱子数量时按剩余需求加权尽量分配，剩余跳过。道具单件 +1、中心拾取、下轮生效等仍是原玩法语义。

固定模式替代片段：

```json
{"Items":{"mode":"fixed","placements":[{"type":"vision","position":{"x":2,"y":0}}]}}
```

联机只为一局覆盖道具：

```json
{"type":"match.create","payload":{"playerCount":2,"manualTickAdvance":true,"seed":42,"items":{"mode":"random","seed":12345,"counts":{"speed":3,"capacity":3,"range":3,"vision":3}}}}
```

## 7. Initial 测试环境

文件 Initial、建局 initial、脚本 initial 使用同一结构，整块替换。省略时使用正式固定地图及文件 Player 属性。

| 字段 | 要求／省略行为 |
| --- | --- |
| map | 必填 empty，以空21×21地图为基础 |
| walls、crates | 可选{x,y}数组，各坐标0～20，箱子不能与已设障碍重叠 |
| players | 必填数组，长度等于实际人数，编号唯一覆盖1..N |
| players[i].playerId、.position | 必填，出生格为空地，玩家可同格 |
| players[i].speed、.capacity、.range | 可选正整数，省略继承文件 Player 对应值 |
| players[i].vision | 可选非负整数，省略继承 Player.VisionRadius |
| players[i].lifetime | 可选正精确时间，省略继承 Player.BubbleLifetime |
| bubbles | 可选数组，每颗包含 ownerId、position、placedAt、dueAt |
| bubbles[i].ownerId、.position | 归属1..N，位置为空地，初始数量不超容量，同格可多颗 |
| bubbles[i].placedAt、.dueAt | 整数或分数，placedAt≤0、dueAt≥0，dueAt=placedAt+所属玩家lifetime |

改变实际人数时，文件 Initial.players 必须匹配，或同时覆盖 initial／设 null。固定道具按最终地图校验。

## 8. Logging

| 键 | 默认值／用途 |
| --- | --- |
| Logging.LogLevel.Default | Information，未被更具体规则覆盖的最低级别 |
| Logging.LogLevel.Microsoft | Warning |
| Logging.LogLevel.Microsoft.Hosting.Lifetime | Information |
| Logging.LogLevel.QQT.Simulation.Tick.Movement | Debug |
| Logging.LogLevel.QQT.Simulation.Tick.Explosion | Debug |
| Logging.LogLevel.<分类名> | 可增加实际分类，更具体规则覆盖父级 |
| Logging.Console.FormatterName | simple；框架还支持 systemd、json |
| Logging.Console.FormatterOptions.SingleLine | true，simple单行输出 |
| Logging.Console.FormatterOptions.TimestampFormat | HH:mm:ss.fff 加末尾空格 |

实际分类：QQT.Server.Battle、QQT.Transport.Ai、QQT.Transport.Ui、QQT.Script、QQT.Simulation.Match、QQT.Simulation.Tick，以及 Tick.Movement／Bubble／Explosion／Map／Death／Item 子分类。可用 Trace、Debug、Information、Warning、Error、Critical、None。

Logging.Console.LogLevel.<分类名> 可指定控制台专用级别。框架扩展见[控制台格式器](https://learn.microsoft.com/en-us/dotnet/core/extensions/logging/console-log-formatter)。日志过滤不关闭JSONL记录，记录写入故障仍中止运行，不改判胜负。

## 9. 实现边界与验收

地图尺寸保持21×21、人数范围2～4、四方向移动、道具单件+1、同刻结算顺序属于结构和玩法。暂停／回放界面、心跳、迟交超时、重连恢复、记录轮转等未实现功能不因配置改造新增。

记录包含配置路径、文件快照、请求覆盖、实际出生／种子、道具分配和事件。实现入口见 [ServerConfiguration.cs](../../src/QQT.Server/ServerConfiguration.cs)，协议变更见[对战协议](../battle/对战协议_逐项确认.md)。

验收输入与预期见[统一配置验收方案](统一配置验收方案.md)。统一入口仍为 `./scripts/verification/verify-battle.ps1`，包括配置检查、既有脚本／网络回归和真实浏览器验证。仅报告实际运行结果，不将文档检查当作程序验证。
