# 首版模拟规则：已确认汇总

本文汇总用户在设计讨论中明确确认的规则，是首版规则依据。基础模拟和首期道具的生成、拾取、生效、范围影响与可见性已确认，可以据此开始验证。完整协议的其他字段和一般实现细节在实施时完善，不阻塞验证程序。本文不是已实现或已通过性能验证的服务端。文档导航见 [文档索引](README.md)，方案比较见 [设计评估与待确认事项](设计评估与待确认事项.md)，时间推演见 [高速移动与事件时间模型](高速移动与事件时间模型.md)。

## 目标与范围

- 用于 AI 比拼的简化泡泡堂规则游戏，不以复现原作为验收目标。
- 当前先实现服务端和附带的浏览器观战 UI，不实现 AI 算法客户端。已确认普通 C# 模拟核心＋单个 ASP.NET Core 服务端进程，兼任 AI 接口与 UI 后端；浏览器采用原生 TypeScript＋Canvas 2D＋HTML/CSS。AI 与 UI 分别使用独立的 WebSocket＋JSON 连接，HTTP 提供 UI 资源与回放读取。
- 首版以 Windows 本机运行与验收：服务端、浏览器 UI 和 AI 接口验证均在本机进行。每个服务端进程同时运行 1 局，可在一局结束后继续开始下一局。每局仍为 4 名 AI，性能通过验证程序运行后评估。
- 首版每局 4 人自由混战、四方向移动；玩家互不阻挡，可以同格。
- 所有玩家初始属性统一：速度 1 格/tick、容量上限 3 颗、每方向爆炸范围 1 格、寿命 3 tick、视野半径 R=2、每轮行动值 10 点。参数最终由配置文件提供，在场泡泡数和剩余行动值随各自操作变化。
- 地图包含不可破坏墙、可破坏箱子和空地。
- 逻辑地图内部为完整 21×21，尺寸不包含 UI 外圈墙。UI 额外绘制外圈硬墙；逻辑越界按阻挡处理，爆炸在边界停止，视野裁剪到内部地图。
- 四名玩家出生在内部地图四个角格中心，每局随机一对一分配并由服务端保存种子以便复现。每角初始仅保证出生格和两个向内相邻格为空地，共 3 格，不放墙或箱子；其他格子按固定布局决定。协议格子位置用从 0 开始的整数对 (x,y)，界面仍用 A～U、1～21。
- 首版使用固定 21×21 初始地图：行、列序号同时为偶数的交点是硬墙，如 B2、D2、B4、D4，直到 T20。除硬墙和四角共 12 格预留空地外，其余全部为箱子；每局恢复该初始布局。共 100 格硬墙、329 格箱子、12 格空地，完整图见 [首版地图布局](地图布局_21x21_首版.md)。
- 受击直接淘汰；首期包含移速、泡泡容量、爆炸范围三种增益道具；不包含困泡救援和复活。

## 模块职责

- AI 客户端是独立决策器：接收服务端场景观察，向服务端请求额外可用信息，提交本 tick 的移动与放置计划。它不承担 UI 展示，也不通过 UI 获取信息或提交决策；首版暂不实现 AI 算法客户端。
- 服务端负责观察裁剪、信息查询与行动值管理、动作收集与验证，以及游戏模拟和胜负结算。
- 服务端附带浏览器 UI，用于展示服务端模拟过程。UI 展示流程与 AI 决策协议相互独立，UI 不负责向 AI 提供决策信号或收集 AI 动作。

具体技术组合与数据流见 [首版系统架构设计](系统架构设计_首版.md)。服务端同时提供 UI 页面资源与数据／控制接口；C# 模拟核心独立于 Web 和 UI，Canvas 只绘制服务端确认的模拟过程。首版采用 Windows＋.NET 10 LTS，目标框架为 net10.0；SDK 与运行时的具体补丁版本在实施时确定。

## AI 通信

每名 AI 使用一条原生 WebSocket 参赛长连接，以自定义 JSON 消息交换决策开始与局部观察、付费查询请求与响应、动作提交与锁定反馈。玩家编号由服务端分配并绑定该连接，在本局跨轮稳定；请求只能操作连接绑定的玩家，不能通过填写其他编号替别人行动。具体登记消息及其他消息字段仍待协议设计。

AI 查询和动作请求均携带 gameId、roundId、requestId，分别标识对局、决策轮与请求响应关联。对局或轮次不匹配时拒绝请求，不扣行动值、不锁定计划。requestId 只用于关联，不改变查询每次成功处理都扣费（包括同 requestId 重发）、动作重发不重复执行的规则；标识类型与具体响应字段仍待设计。

真实 AI 对局先进入准备阶段，四名 AI 均完成登记后，由 UI 手动开始并统一下发首轮观察；不足四人时保持准备状态。准备阶段已登记连接明确关闭或报错时释放其席位，接受新连接登记，不按开局后的规则判出局。脚本验证仍按既定方式由 UI 手动创建／开始。

四名 AI 已登记、席位已满时，额外登记请求明确拒绝并返回“席位已满”，首版不维护候补队列；已有席位释放后可重新申请。一局结束后，服务端发送结束通知并关闭 AI 参赛连接；下一局重新连接、登记并分配玩家编号，不保留跨局参赛连接。

对局开始后，连接明确关闭或发生连接错误时按已确认掉线出局规则处理，不启用心跳超时检测，不支持重连恢复本局参赛资格；动作迟交继续等待。查询成功逐次扣费与动作重发不重复执行的规则保持不变。AI 参赛通道与 UI 全局展示通道采用独立接口与连接，分别传输各自的数据。

首版本机 UI 的全局数据、运行控制与对局记录读取接口不校验访问凭据。UI 与 AI 仍使用独立接口和连接；不新增 UI 凭据要求。

## 首版验证驱动

暂不实现 AI 算法客户端期间，首版提供预设脚本驱动对局验证。脚本采用 JSON 文件，按模拟轮组织各玩家的有序查询与动作请求，创建对局时加载并校验结构。输入经过服务端同一套查询、扣费、动作校验、锁定和模拟规则，结果由既有 UI 展示并保存于对局记录。

该工具执行预设测试输入，不包含 AI 策略算法，也不绕过视野、预算、阻挡或胜负裁决。首版在 UI 选择脚本、可选指定种子，手动创建／开始；结束后保留结果，再手动开始下一局，不自动顺序运行脚本列表。具体脚本字段仍待设计；手动逐轮输入入口不列为首版必做。WebSocket 消息和连接行为仍需接口验证。

对局尚未结束，但本轮脚本执行完仍缺少某位存活玩家的有效计划，包括脚本提前耗尽时，结束本次验证并标记“脚本错误／未完成”，保留现场与记录，不判竞技输赢；修正脚本后新开一局。此规则只用于验证工具，不改变正式 AI 在线未提交时继续等待的规则。不能用脚本错误替代真实胜负结果。

## 首版配置参数初始值

游戏数值配置采用 JSON，在每局创建时读取并固定为本局配置。对局进行中修改文件只影响之后新建的对局，不中途改变当前局规则；实际使用的配置写入对局记录。本表记录已确认初始值，具体字段与校验细节仍待设计。

创建新局时，配置无法读取、JSON 格式错误或参数不合法，拒绝创建并在 UI 显示具体原因，修正后重试。不自动使用默认值或上一份有效配置代替。

## 决策与连接规则

### 1. 整数移动速度

首版速度限定为整数格/tick，已确定统一初始速度为 1 格/tick，可由移速道具提升。tick 是统一 AI 决策周期；T=1 个抽象逻辑时间单位，可表达 0.5 tick 等途中时刻，不绑定现实毫秒。观战播放时长另行配置，不改变模拟结果；道具从下一轮生效，不改变本轮速度与已提交计划。

选择移动时，计划距离为该速度对应的整数格数；角色按匀速逐格推进。在未淘汰、未遇阻时，tick 末位于格子中心；遇阻也在中心截停。下一轮可以在中心重新选择方向，不需要处理存活玩家处于格间时的新轮改向。

### 2. 未提交则整局继续等待

在收集本轮计划时，逻辑时间冻结。仍在线的存活参与者未提交有效计划，就继续等待，不因迟交自动生成等待动作或淘汰，也不推进游戏。掉线玩家按下述独立规则出局，不再作为需要等待的存活参与者。

等待期间移动、泡泡计时、最大 tick 数都不增长。现实决策耗时可以用于等待提示和统计，但不因动作迟交自动代走或淘汰。等待不恢复本轮已经消耗的行动值；首版不支持重连恢复。

### 3. 首次有效提交锁定

每个玩家的首次有效移动与放置计划一旦提交，本轮即锁定：

- 不允许替换方向或放置计划。
- 不再接受该玩家本轮信息查询。
- 动作重发只确认原计划，不重复执行移动或放置。
- 已提交者等待其他玩家期间，也不能重新查询或修改。
- 出现非法方向，或放置位置不在所选方向的计划路径上时，整份计划拒绝并返回原因，不执行其中任何内容、不锁定本轮；玩家可修正后重交。
- 合法方向上的实际阻挡按截停规则处理，不因此拒绝计划；执行时容量不足只失败当次放置请求。
- 无效提交不属于首次有效提交；具体错误反馈字段仍待协议定义。

动作重发与查询重发是两种规则：信息查询只要再次成功处理，包括同 requestId 重发，仍再次扣费；动作重发不重复执行。

### 4. 开局后掉线直接出局，不支持重连恢复

对局开始后，服务端判定玩家掉线，该玩家出局，不能通过重连恢复本局参赛资格。其未执行计划取消，已放泡泡仍按淘汰者规则保留；对局仍进行时继续计时和爆炸。掉线与仍在线但迟交动作不同，迟交继续等待。准备阶段连接关闭或报错只释放席位并允许新连接登记。

首版只在连接明确关闭或发生连接错误时判定掉线，不增加心跳超时检测。动作迟交、信息查询失败或无效动作不属于连接错误。网络中断但服务端尚未收到连接关闭或错误通知时，不据此自动淘汰，仍可能继续等待。

等待决策时收到掉线通知，就在当前逻辑时刻处理出局，不推进移动或泡泡计时；取消该玩家未执行计划，并检查胜负。仍有多人存活时，只等待剩余存活玩家的有效计划。

正在模拟时收到掉线通知，在下一个内部事件结算点处理：先完成位置推进，取消掉线者未执行计划，再结算同刻到期与连锁，合并掉线与受击淘汰后统一检查胜负。对局结束则不执行该点后续放置或移动，不在同刻爆炸尚未结算前先判掉线胜负。

等待期间有人掉线但对局仍继续时，通知剩余玩家掉线者的稳定玩家编号，保留其余玩家本轮原观察与已查询结果，不重新生成决策轮。掉线玩家从可查询目标中禁用，查询失败不扣行动值；其已放泡泡仍保留，视野内泡泡仍按本轮原编号和快照查询。

其余玩家剩余行动值不重置，已锁定计划不撤销、查询仍关闭；未提交者继续查询和提交。通知掉线编号是本轮额外状态通知，不额外披露位置、视野外地形或泡泡详情。

## 一轮的流程

1. 完成旧轮终点的到期爆炸、连锁、淘汰与终点放置；若对局已结束，不进入下一轮。
2. 统一应用上一轮已拾取的待生效增益，再恢复本轮固定行动值，生成同一逻辑时刻的冻结状态，为各玩家裁剪局部观察。
3. 未提交者可以请求付费信息；查询读取同一份冻结游戏状态，自身剩余行动值随查询更新。
4. 玩家首次有效提交后锁定并关闭本轮查询。
5. 未收齐则继续等待；收齐所有存活参与者的计划，且满足最小推进间隔与运行／单步控制后，共同模拟本轮。
6. 服务端按内部事件时刻结算，期间不向 AI 开放新决策机会。
7. 抵达下一 tick 终点，处理旧计划终点事件；对局未结束则生成下一轮观察。已经处理的同刻爆炸和请求不重复执行。

内部事件可以发生在 T/3 等途中时刻，不推迟到大 tick 或固定小模拟步边界。内部使用分数 tick 精确运算，例如 1/3+2/3=1，据此比较事件先后和同刻，显示时可转换小数，显示舍入不参与裁决。对外时间采用分子、分母整数对象，例如 {"numerator":1,"denominator":3} 表示 1/3 tick，整数 3 tick 表示为 {"numerator":3,"denominator":1}。推荐按事件时刻分段推进；具体调度实现仍待定。

## 移动与阻挡

UI 外圈硬墙表示地图边界，不占逻辑地图坐标。内部 21×21 格仍可分别布置空地、硬墙和箱子，并非所有内部格都保证可通行。按上一题一格厚外圈的表现方案，UI 总格位为 23×23，中间 21×21 对应逻辑地图；外圈不参与放置、查询或爆炸覆盖。

- 一轮选择一个固定方向，或选择整轮原地等待。
- 不允许途中主动改向或停止；不包含先等待一段时间再启动的动作能力。
- 只在格子中心开始下一段相邻格移动；完整路径逐格检查，不能仅检查终点。
- 在中心发现下一格越界或被墙、箱子、泡泡阻挡，停在当前中心并终止本轮剩余移动。
- 阻挡稍后消失，也不自动重启；未到达位置的放置请求不执行。
- 泡泡生成时已经在该格的所有玩家均可离开；离开后不能重新进入仍存在的该泡泡格。
- 已开始的一格移动允许完成，即使目标格途中新放泡泡，到达后也可离开。
- 离开许可针对具体泡泡，离开或泡泡消失后失效，不表示该格永久通行。

## 首期道具

首期计划实现以下三种道具，替代此前“首版不包含道具”的范围约定：

| 道具 | 属性效果 |
| --- | --- |
| 移速增加 | 每 tick 的移动速度增加 1 格 |
| 泡泡容量增加 | 玩家同时在场的泡泡数量上限增加 1 颗 |
| 爆炸范围增加 | 玩家泡泡的每方向爆炸范围增加 1 格 |

统一初始属性保持为速度 1 格/tick、容量 3 颗、每方向范围 1 格。道具规则补充如下：

- 每局配置三类道具各自的数量。开局时在箱子中随机预分配，每个箱子最多一件；不是箱子被破坏时再按概率随机生成。保存种子与实际分配，箱子被毁后其道具才成为场上可拾取实体。
- 玩家到达格子中心且存活时拾取。同一时刻到达同一道具中心的玩家都获得该增益；先统一确定获得者，再移除该道具，不能按玩家遍历顺序只发给一人。
- 拾取增益先记为待生效，从下一 tick／决策轮开始生效。先完整处理旧轮终点事件，再统一应用增益、生成下一轮观察；旧轮终点爆炸仍使用旧属性。本轮已提交计划、移动速度、容量和爆炸范围不因本轮拾取而改变。
- 增益生效后持续到对局结束，多次获得可累积，不设置属性上限。
- 下一轮起爆炸的泡泡，包括此前已放出的泡泡，都使用所属玩家在该轮已生效的爆炸范围；范围不固定为放置时的值。连锁提前引爆也按实际爆炸所属轮的已生效范围计算。
- AI 免费观察只提供视野内已露出道具的位置和类型，不公开箱子中预分配的隐藏道具。UI 与对局记录可以保存全局分配与状态。
- 爆炸覆盖此前已经露出的道具时，该道具被销毁；同批箱子销毁后新掉落的道具保留，不被产生它的这批爆炸销毁。

每类道具的初始数量尚未指定，由配置文件明确提供；分配算法属于实现细节，建议对箱子位置做有种子的随机洗牌，再按配置数量分配。

## 沿途放置

轮初可以预选本轮路径中的格子中心放置，包括起点。到达对应中心且存活才尝试放置，不允许对未到达位置远程放置。

- 每个玩家每轮在每个中心最多请求一颗。
- 同格允许多颗，可来自不同玩家或不同轮次；已有泡泡不造成占格竞争失败。
- 容量限制每个玩家同时在场的泡泡颗数，初始上限为 3 颗；不按占用格数计算，也不是单轮请求数上限。
- 每次实际放置检查容量及合法条件；当次失败不取消移动或其他放置，并反馈原因。
- 同刻先处理全部放置，再检查下一格阻挡、启动新移动段。
- 截停中心若是已选放置位置，存活者仍按正常条件尝试；只有未到达位置不执行。

每颗记录实际放置时刻 p、固定寿命 L 和归属，预定到期为 p+L；初始配置 L=3T，即放置后三个逻辑 tick 到期。范围使用所属玩家在实际爆炸轮的已生效属性，放置时范围只可作为历史信息，不能固定后续伤害范围。所有泡泡独立计时，连锁可以提前引爆。同格一颗爆炸立即连锁其余泡泡，每颗按其所属玩家当轮的范围产生覆盖并释放容量，一颗只结算一次。

在未获得移速增益、速度 1 格/tick、中心放置和寿命 3 tick 的初始配置下，正常放置产生的预定到期集中在 tick 边界；这不撤销此前确认的途中引爆能力，也不将一般事件时间重新取整到边界。后续配置或单独验证场景仍可以使用途中到期时刻。

## 同刻结算与爆炸

1. 把所有玩家推进到事件时刻，得到合法位置和进度。
2. 处理本结算点的待处理掉线，取消掉线者未执行计划；保留其已放泡泡。
3. 按爆炸开始前同一份墙、箱子、泡泡及已露出道具状态，使用各所属玩家当轮已生效范围，计算全部到期与连锁覆盖。
4. 统一移除已爆炸泡泡、被毁箱子和覆盖内原有露出道具；释放被毁箱子中预分配的道具，新掉落者不受本批爆炸销毁。按同刻玩家位置判定受击，合并掉线与受击淘汰。
5. 立即检查胜负；对局结束则停止，不执行后续步骤。
6. 对存活且到达道具中心的玩家统一处理拾取，增益记为下一轮待生效，再移除已拾取道具。
7. 对存活者统一执行该时刻放置请求，容量仍按本轮已生效值检查。
8. 检查阻挡并开始下一段移动；旧轮终点没有剩余移动预算，不多走一格。

爆炸瞬时造成伤害，不保留持续危险区。按玩家中心所在格判定：相邻格移动小于半程归起点格，达到半程归目标格。只看引爆时刻位置，曾经经过危险格不等于受击。动画播放不产生持续伤害。

| 射线遇到的对象 | 已确认处理 |
| --- | --- |
| 硬墙 | 不覆盖墙格，射线停止 |
| 箱子 | 覆盖箱子格、销毁箱子，射线停止 |
| 另一格泡泡 | 覆盖该格、触发连锁，原射线按剩余范围继续 |

同刻一颗炸毁箱子，不会让另一条同刻射线穿过它；全部覆盖算完才统一清理。清理后的环境用于随后放置与新移动段检查。恰好到达安全格可以避开爆炸，同刻才发起的移动不能改变引爆时刻位置。

## 位置编码

协议使用从 0 开始的整数格子坐标对 (x,y)，x 向右、y 向下，范围各为 0～20。界面标注仍为列 A～U、行 1～21：A1=(0,0)，B2=(1,1)，U21=(20,20)。四个出生位置为 (0,0)、(20,0)、(0,20)、(20,20)，每局随机分配给玩家。

人读坐标行列序号同时为偶数的硬墙，在从 0 开始的协议坐标里对应 x、y 同时为奇数，不能混用判断。整数对表示格子，JSON 采用对象形式，例如 {"x":0,"y":0} 表示 A1。跨格移动仍记录起点格、终点格和进度；精确时间运算与途中受击规则保留。

动作中的泡泡放置计划使用格子坐标对象列表，服务端校验各位置是否属于所选方向与速度构成的计划路径，包含起点；等待时只能选择当前格。列表表示选择的格子，实际放置时刻仍由到达中心决定。例如速度为 3、从 A1 向右的演示计划，可用 [{"x":0,"y":0},{"x":2,"y":0}] 选择 A1、C1。未到达、淘汰或容量不足仍按已确认执行规则处理；列表重复项及越界坐标等校验边界在实施时完善，涉及玩法语义的新歧义再确认。

## 可见信息与行动值

视野以角色中心所属格为中心，横纵距离分别不超过 R，形成方形并裁剪地图边界。墙、箱子不遮挡；地形和实体只显示视野内，视野外未知。

每轮观察只发送视野内格子的坐标与地形，以及视野内实体列表；不发送完整地图矩阵。未发送的地图格子视为本轮未知，不代表空地。客户端可以自行保留历史记忆，但服务器不将视野外的历史信息作为本轮最新状态下发。

| 信息对象 | 免费信息 | 付费信息 |
| --- | --- | --- |
| 自身玩家 | 全部自身游戏状态，含位置、速度、容量上限、在场泡泡数和剩余行动值 | 自身泡泡详情仍不免费 |
| 可见其他玩家 | 位置、跨轮稳定玩家编号 | 身份（即该编号）、速度、容量上限、在场泡泡数；不返回剩余行动值 |
| 可见泡泡，包括自己的 | 位置、本轮局部查询编号；同格多颗分别编号 | 归属、范围、准确预定到期，按颗一次返回完整详情 |
| 可见已露出道具 | 位置、类型 | 首期没有道具详情付费查询 |

泡泡编号本轮固定、下轮重新分配；玩家编号跨轮稳定，但不授权查询当前视野外玩家。查询其他玩家的在场泡泡数可包含其视野外泡泡，不披露那些泡泡的位置。

行动值只用于查询，移动和放置不消耗。初始单价为每颗泡泡详情 1 点、每位其他玩家详情 2 点。每轮恢复初始额度 10 点，未用部分不累积。每次成功查询都扣费，重复与网络重发也扣费；失败不扣费、不返回详情。提交计划后本轮查询不再接受，因此不会成功扣费。

客户端可以记忆和推断，例如根据自己成功放置的时刻与固定寿命计算预定到期。查询披露的是预定到期，实际引爆可能被连锁提前；泡泡范围对应当前轮已生效值，之后所属玩家的新增益可能改变其未来爆炸范围。

## 浏览器观战

首版 UI 展示服务端掌握的完整游戏信息，用于观察游戏进行及评估各个 AI 的决策能力。展示范围包含整张地图地形、所有玩家的位置与状态、所有泡泡的位置、归属、范围与预定到期时刻，以及移动、放置、爆炸、淘汰和对局结果等模拟信息。UI 不受 AI 局部视野或付费详情查询的展示限制。

UI 采用独立 WebSocket＋JSON 接收全局状态与事件，并发送暂停／继续／单步控制。HTTP 提供页面、静态资源与回放记录读取。关闭 UI 连接不构成 AI 参赛掉线，不因此淘汰玩家。

首版优先实时观战，最小 tick 推进间隔初始为 1 秒，可配置，按相邻两轮实际开始模拟的现实时间计时。首轮在已开始运行且收齐有效计划后即可模拟，不等待前一轮间隔。后续收齐存活玩家的有效计划且距离上一轮实际开始已满足间隔，才按运行／暂停及单步控制推进；不等待浏览器播放完成回执，也不以浏览器帧率计逻辑时间。

例如上一轮在现实 0 秒开始，下一轮在 0.2 秒收齐，则最早在 1 秒开始；若在 1.8 秒才收齐，可在 1.8 秒开始。此后下一轮的间隔从实际的 1.8 秒重新计时。间隔是开始时刻之间的下限，不要求模拟计算持续 1 秒。AI 未提交仍继续等待，不因间隔已到自动补动作或淘汰；现实运行节奏不改变精确逻辑时间、速度、寿命与胜负规则。

正常动画和回放 1 倍速的基准时长初始为 1 秒／逻辑 tick，独立于服务端最小推进间隔配置。UI 按已确认过程的逻辑时间比例展示移动与事件，不改变服务端逻辑时间或 AI 决策规则。

实时 UI 按已模拟完成、尚未开始播放的轮数计积压，当前正在播放的一轮不计入，不按 WebSocket 消息或事件数量计数。积压达到 2 轮时触发追赶，阈值可配置：跳到服务端最新完整全局状态，跳过积压动画；完整事件日志与对局记录仍保留，跳过过程可通过回放查看。不因 UI 落后暂停服务端，运行控制仍作用于服务端当前对局。

首版 UI 以全局游戏状态与事件日志为展示内容，不加入选中 AI 的详细分析面板。各 AI 的局部观察、查询响应与扣费、决策及执行过程仍保存于对局记录，详细分析通过记录查看。

AI 客户端与 UI 独立：AI 仍只能通过自己的协议获取局部观察及按规则查询额外信息，UI 展示全局信息不会改变 AI 的信息规则。展示范围、播放节奏、积压追赶与控件已确认；具体布局在实施时完善。

首版 UI 提供暂停／继续和按 tick 单步，用于控制服务端模拟。暂停在 tick 边界生效；单步仍须收齐所有存活玩家的有效计划，推进最多一个 tick 后暂停。若推进中触发胜负，则立即结束，不为了走满 tick 而继续。暂停或单步不替代 AI 提交决策，也不放宽既有动作规则。

### 对局记录与回放

首版保存对局记录并支持 UI 回放，用于事后分析各个 AI 的行为。记录存于服务端本地目录，每局一个 JSONL 文件，在对局过程中逐条追加保存，结束后保留，UI 可选择记录回放。记录包含本局实际配置与地图、种子、AI 观察／查询／决策、模拟事件和掉线逻辑时刻；查询保留处理结果与扣费。具体字段与目录仍待设计。

对局进行中记录写入失败时，停止进一步 tick 推进，在 UI 显示错误，保留当前现场与已写记录，不因存储错误改判竞技胜负。首版不做故障后同局恢复：暂停且尚未结束的对局由人工终止本次运行并标记未完成，不判竞技输赢，修复后新开一局，不重新执行旧局请求来恢复。

验证未完成或运行中断的记录，允许回放已成功保存的完整有效前缀，明显标记“未完成”。只展示已保存数据，不补模拟、不推断缺失的胜负。未完成是记录／运行状态，与正常竞技平局区分。

回放读取已记录的过程，不重新向 AI 请求决策，不依据回放时的网络到达顺序重新裁决比赛。UI 回放支持播放／暂停、向前／向后逐 tick 查看和按 tick 跳转，不修改真实对局、不请求 AI 新动作。首版固定 1 倍速，不提供倍速选择；基准时长初始为 1 秒／逻辑 tick，仍按已确认配置使用。具体记录与回放接口字段待设计。

## 对局结束

- 自由混战，最后存活的玩家获胜。
- 一批同刻到期、连锁和统一淘汰全部完成后检查：剩一人立即获胜，零人平局。
- 不能在同批连锁中间先宣布胜负，也不继续到 tick 末才检查。
- 已结束即停止模拟，即使稍后有泡泡可能击中获胜者，也不继续推进。
- 淘汰者未执行的计划取消，已放泡泡保留归属并继续计时；只有对局仍进行时才继续模拟它们。
- 最大 tick 数初始值为 500，现实等待不计入。第 500 tick 终点先结算到期、连锁和统一淘汰：剩一人或零人立即按已有规则结束，不执行后续放置；若仍多人，完成旧计划终点放置后宣布超限平局，不启动新移动段、不生成第 501 轮观察。
